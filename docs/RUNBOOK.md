# 生产发布与应急回滚手册（Operations Runbook）

## 热点 SKU 乐观锁争用应急预案

### 识别与告警

在运维看板检查库存表的“高冲突”标签，并查看 `/api/state` 返回的指标：

- `inventory_optimistic_lock_retry_total`：全局乐观锁重试总数。
- `inventory_optimistic_lock_retry_total{sku="..."}`：对应 SKU 的重试数；关注监控周期内的增量，而非进程启动以来的累计值。
- `inventory_restock_latency_ms_bucket{sku="...",le="..."}`、`_count`、`_sum`：按 SKU 记录的回补延迟直方图。看板按桶显示近似 P95；持续进入更高延迟桶说明争用或存储变慢。
- 库存表中的“低库存”标签表示可用量不高于 3；“高冲突”标签表示该 SKU 累计至少 5 次乐观锁重试。阈值是看板默认值，应结合业务告警窗口及流量调整。

指标当前由进程内存维护，重启后会清零。需要判断趋势时，请结合连续采样值及应用日志；不要把进程重启前后的计数直接相减。

### 处置步骤

1. 记录受影响 SKU、冲突计数增量、回补延迟桶、可用/预占数量及事件审计记录；确认是否集中在促销流量或单一调用方。
2. 若争用仍在上升，通过现有流量治理手段临时降低该 SKU 的新订单写入速率，必要时暂停该 SKU 的促销入口。不要关闭取消处理或库存回补消费者。
3. 等待在途回补完成，观察冲突增量和延迟桶是否回落；检查数据库超时、服务资源及消费者积压，再逐步恢复写入。
4. 若应用版本或配置变更与故障时间吻合，停止继续发布并回滚到最近稳定版本；回滚期间继续保留取消事件处理和幂等校验。
5. 恢复后核对可用库存、预占库存、取消订单及审计记录。严禁通过直接修改库存数或绕过幂等键来“清零”冲突。

### 死信事件安全重放

检查 `/api/state` 中 `dlq` 的事件、失败原因和尝试次数，先修复超时或数据问题。逐条重放并确认订单、SKU、数量和幂等键正确；重放后核对库存与审计记录。消费端确认幂等前不得批量重放，也不得对同一事件同时执行人工库存补偿。
